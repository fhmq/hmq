# HMQ v4.1.0

## Durable MQTT sessions

- Persist inbound and outbound QoS 2 handshake state and messages for resumable
  sessions in the standalone WAL and opt-in Raft quorum profile. Reconnect with
  the same Client ID to continue the exchange after restart or a node change.
- Add the SessionStorage interface for standalone embedders. The built-in
  backends are the local WAL and Raft; no external database driver is bundled.
- Support MQTT 5 non-expiring durable sessions when a backend is configured.
  Finite session expiry timers are not implemented.

## Capacity and recovery

- Add per-session message and byte limits via sessionQuota, and monitoring at
  GET /api/v1/capacity. Quota rejection does not partially enqueue durable fanout.
  If a target fills between PUBREC and PUBREL, the pending exchange is preserved
  and no successful PUBCOMP is sent.
- Snapshot durable subscriptions, queues, ownership versions and QoS state.
  Reclaim only history covered by every member's fsynced delivery cursor and
  preserve the suffix needed by lagging nodes. Require the covering snapshot
  during recovery before relying on the compacted Raft WAL.

## Broker fixes

- Validate legacy MQTT frames before dispatch and limit incoming MQTT 3.x and 5
  packets to 1 MiB. Incomplete frames no longer allocate their advertised size.
- Process each connection's packets in order without a shared MQTT work queue,
  and disconnect slow consumers without blocking unrelated connections.
  Includes regressions for issues #208, #177 and #178.

## Upgrade and verification

Upgrade all quorum members together. The compact snapshot peer protocol is not
compatible with rolling upgrades from the old session-persistence profile.
Back up snapshots and both Raft and delivery WALs together; do not downgrade a
compacted data directory. A member that stops consuming can pin history until it
catches up. These guarantees apply to durable fanout, not exactly-once business
processing or transient socket delivery.

Local verification covers the full Go race suite, a 60,000-message QoS 1/2
regression, quota saturation, snapshot installation by a lagging follower,
leadership change, and full-cluster restart. The repository also has an opt-in
Docker Compose regression suite for standalone and quorum deployments. Compose
requires a source checkout or source archive. Kubernetes deployment changes are
not part of this release.
