# HMQ v4.0.2

## Deployment and Tests

- Add a local Docker Compose environment with standalone and three-node quorum
  profiles. Broker images build from the checked-out source. Host ports bind only
  to 127.0.0.1; cluster and Raft ports are not published.
- Generate a local CA, distinct mTLS node certificates and a random shared secret
  in an initialization service. Preserve credentials and per-node durable data
  across ordinary container restarts; no private keys are committed or bundled.
- Add opt-in real-container tests for QoS0/1/2, wildcard subscriptions, retained
  replay, MQTT 5 properties, mixed-version delivery and Will publications.
- Test follower-originated cross-node delivery, leader failover, loss of the
  majority, whole-cluster restart, delivery-cursor recovery and subsequent delivery.
- Add a Compose integration CI job. Normal Go tests skip the container suite unless
  HMQ_COMPOSE_TEST=1; the dedicated job explicitly enables it and exercises Docker.
- Include deployment/validation documentation in binary archives. Compose itself
  requires a source checkout or GitHub source archive, not just the binary archive.

## Fix

JSON configuration with plugins.bridge="none" or an empty bridge name previously
created a non-nil mock bridge. Quorum consequently rejected an otherwise valid
configuration as having an enabled bridge plugin. Disabled bridge configuration
now remains nil while authentication is still initialized. The existing bridge
factory API is unchanged. A regression test covers this configuration path.

## Verification and Limits

The local Compose environment was actually deployed with four broker containers.
The race-enabled container suite passed, including leader b failing over to c,
no success acknowledgment without a majority, and persistent cursor recovery
after a complete cluster stop/start. Full repository race regression and static
checks passed. See deploy/compose/VALIDATION.md for the recorded local run.

The deployment is for local evaluation, with permissive authentication and a shared
read-only credential volume, not production authentication/key isolation. Quorum
is still experimental, fixed single-partition, clean-session QoS0/1 only. These
tests do not establish multi-host, production-load or power-loss guarantees.

The Go module remains github.com/fhmq/hmq/v4 and requires Go 1.27.4 or newer.
Release automation builds five platform archives with SHA256 checksums; check the
published workflow and assets for completion. The vulnerability scan reports no
reachable or imported-package vulnerabilities; an unused openpgp module-level
advisory remains, so this is not a claim of zero module-level advisories.
